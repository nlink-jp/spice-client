# レビューと新実装での対処

2026-09-17。元プロジェクトの76ファイルを対象とした確認では、意図的なバックドアや隠れた第三者送信を示す根拠は見つかりませんでした。一方、下記の認可・TLS・Cookie・終了処理などの問題を確認しました。

元コードは変更せず、新規アプリで対処しました。[元版の詳細レビュー](baseline-review.ja.md)は過去の状態についての記録です。

| ID | 元版の問題 | 新実装の対処・確認 |
|---|---|---|
| R1 | 自動遷移・フォーム送信を人の承認と誤認 | 変更不能な候補をネイティブ確認で一度だけ消費。実WebKitの自動遷移・POSTを試験 |
| R2 | 古い更新ライブラリ・旧配布元の継承 | Sparkle、更新鍵、フィードを新アプリから除外 |
| R3 | origin判定でscheme・portが不足 | HTTPS scheme・host・実効portとメインフレームを照合 |
| R4 | リダイレクト後にCookieを再選別しない | 専用一時セッションで毎回再選別。実HTTPSサーバーの受信Cookie漏れ0を確認 |
| R5 | 不正tls-portが平文へ切り替わる | 不正な数値・範囲を拒否。有効TLSを優先し失敗時は終了 |
| R6 | secure-channels要求を無視 | 既知チャンネルだけ受理し、TLSの存在を必須にする |
| R7 | 入力の終了待ちが切断を妨げる | 同期的に入力を止め、通信を先に閉じてから待つ。停止する送信の回帰テストを追加 |
| R8 | 接続成功前に元ファイルを移動 | 成功後に一度だけ移動。inode・内容の照合と競合時の復元、終了時の完了待ち |
| R9 | Metalの代理コマンドの存在だけ確認 | doctorで実コンパイル。完成appの両metallibを実読み込み |
| R10 | 依存版数とライセンス記載の不整合 | SwiftSpice 0.4.2とネイティブ28項目を固定。418ファイル・パッチ・リンクを照合 |
| R11 | ソース文字列検査が誤った挙動を固定 | 解析結果・UI承認・実通信・実クリップボード境界を動作で検証 |
| R12 | 配布ゲートが不十分 | packageにテスト・Developer ID・公証を必須化。最終ZIPを展開検査し不正ZIPを拒否 |

独立レビューで見つかった、MJPEG再接続後の共有停止、同じポータルからの2台目の受付停止、最終ZIPの取り違えを見逃す問題も修正しました。実WebKit試験では、Swiftの非同期認証delegateの正しい名前 `webView(_:respondTo:)` に実際の問い合わせが届くことを確認しました。HTTPSのgzip応答と本文切れも試験しています。

実アプリのファイル選択では、別クライアントのUTI登録に依存して `.vv` を選べない問題が発生しました。拡張子での選択判定と、読み込み時の通常ファイル・上限・内容検証に分離しました。

SwiftSpiceの変更は実クリップボードアクセスの許可・世代検証に限定し、元のネイティブバイナリは変更していません。依存全体のバイナリ動作や、実ゲストの相互運用まで「安全」と保証するものではありません。[検証記録](verification.ja.md)と[全ファイル対応表](source-map.ja.md)を参照してください。
